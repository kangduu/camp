## Ask / Debug / Plan / Agent 模式的区别

Cursor 客户端的这四种模式是设计给不同开发场景的，理解它们的核心权限与职责是高效使用 Cursor 的关键。

### 🔍 核心差异：一句话定位

- **Ask**：你的专属**技术顾问**，只回答问题，不碰代码。
- **Plan**：白板前的**架构师**，负责设计方案，但不负责具体实现。
- **Agent**：**自动驾驶的实习生**，全权负责从分析到执行，但可能需要你最后把关。
- **Debug**：专注的**排障专家**，专门分析错误、定位和修复 Bug。

### 📊 详细对比表

| 维度           | 🤖 Agent                                              | 📝 Plan                                                    | 🐞 Debug                                                       | 💬 Ask                                         |
| -------------- | ----------------------------------------------------- | ---------------------------------------------------------- | -------------------------------------------------------------- | ---------------------------------------------- |
| **核心定位**   | **全自动执行者**：像工程师一样思考、规划并执行        | **计划制定者**：先规划、后执行，提供可审核的蓝图           | **问题诊断者**：基于证据（日志、堆栈）分析并修复错误           | **知识顾问**：只回答问题、解释概念，不修改代码 |
| **权限级别**   | **高**：可读、写、执行命令，全自动操作                | **中**：只读不写，生成计划，修改需经确认                   | **中**：可读、可插入日志代码进行诊断，修复需确认               | **低**：完全的只读模式，最安全                 |
| **典型场景**   | 完整的跨文件功能实现、大型重构                        | 架构设计、复杂需求梳理、技术方案评审                       | 终端报错分析、性能瓶颈排查、逻辑异常修复                       | 理解陌生代码、学习技术概念、探索实现思路       |
| **能力范围**   | 全项目代码搜索、多文件编辑、创建文件、运行 shell 命令 | 生成分步计划、使用 Mermaid 图表可视化、分析依赖影响        | 分析终端输出和日志、提出并验证错误假设、插入诊断日志           | 搜索代码库、解释代码片段、回答技术问题         |
| **工作流程**   | 理解需求 → 制定计划 → 探索代码 → 执行修改 → 自主验证  | 分析需求 → 生成执行计划 → 用户审阅确认 → (可选)转Agent执行 | 描述/粘贴错误 → 分析原因并提出假设 → (可能)插入诊断日志 → 修复 | 提问 → 获取答案/建议                           |
| **常用指令**   | `@file` 引用文件、`/edit` 发起修改                    | `/plan` 或 `--mode=plan` 启动规划                          | 直接粘贴错误日志，或使用 `Bugbot` 功能                         | `/ask` 或 `--mode=ask` 开始提问                |
| **风险与建议** | 建议在 Git 分支或干净工作区操作，避免意外修改         | 对于复杂任务，跳过 Plan 模式可能导致 AI 输出偏差           | -                                                              | 仅限于提供信息，无法执行任何操作               |

### 🎯 如何选择？一个推荐的协作流程

1. **首选用 `Plan` 规划**：面对复杂需求，先进入 Plan 模式，让 Cursor 帮你理清实现思路和步骤。
2. **细节用 `Ask` 答疑**：对计划中任何技术细节有疑问，切换到 Ask 模式，安全地提问学习。
3. **主体用 `Agent` 实现**：确认计划无误后，切换到 Agent 模式，让它根据方案自动编写代码。
4. **遇错用 `Debug` 排查**：实现过程中遇到 Bug 或报错，切到 Debug 模式，精准定位并修复。
